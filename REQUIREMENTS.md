# PrintForge — требования для Kimi K3

Версия требований: 1.0. Дата: 21 октября 2026 года.
PrintForge — рабочее название проекта, которое можно изменить без влияния на требования.

## 1. Задача и ожидаемый результат

Разработать самостоятельное настольное приложение для создания и изменения моделей, предназначенных для 3D-печати. Пользователь должен уметь спроектировать корпус, крышку, кронштейн, втулку, переходник или другую практическую деталь без предварительного освоения профессиональной CAD-системы.

Основные приоритеты, в порядке обязательности:

1. Понятное управление и встроенное обучение: пользователь понимает назначение кнопок и может в любой момент открыть пошаговый справочник.
2. Настоящая точная геометрия, редактируемые размеры и зависимости между элементами.
3. Надёжное сохранение, отмена действий и передача модели в слайсер.
4. Самобытный рабочий интерфейс на основе Impeccable и Taste Skill, с проверкой реальных состояний и минимизацией шаблонных AI-приёмов.
5. Широкий набор операций, раскрываемый постепенно по мере необходимости.
6. Необязательный AI-помощник для объяснения интерфейса и создания проверяемых планов моделирования.

Нужно получить работающее приложение с исходным кодом, инструкцией запуска, примерами моделей и подтверждёнными проверками. Красивый экран, демонстрационная сцена или набор неработающих кнопок не считаются готовым результатом.

Справочник, подсказки и учебные сценарии входят в продукт с первого пользовательского этапа. Их нельзя переносить в конец разработки.

### 1.1. Две разные роли AI

Kimi K3 — агент, которому поручается разработка приложения.

AI внутри PrintForge — отдельная необязательная возможность. Она может использовать локальную модель или явно подключённый облачный API. Подписка на агента разработки не должна считаться автоматически доступным API для пользователей приложения.

Приложение, геометрическое ядро, сохранение, экспорт и встроенное обучение полностью работают при отключённом AI.

### 1.2. Рабочие допущения

Для первого релиза принять следующие проектные решения:

- Основная платформа — macOS на Apple Silicon. Контрольная конфигурация — MacBook Pro M3 с 8 ГБ объединённой памяти.
- Первые сценарии ориентированы на функциональные детали для FDM/FFF-печати.
- Основной язык интерфейса, обучения и пользовательских ошибок — русский. Структура строк допускает последующую локализацию.
- Основные единицы — миллиметры; внутренние расчёты используют согласованную систему единиц.
- Работа с документами локальная, без обязательной регистрации и сервера.
- Код хранится в Git. Публичная публикация, создание удалённого репозитория и размещение релиза выполняются только по отдельному указанию владельца.
- Архитектура должна допускать последующие Windows и Linux, но их поддержку нельзя объявлять без фактических сборок и проверок.

Это выбранная стартовая конфигурация проекта. Она не означает, что пользователь запретил другие платформы.

## 2. Объём продукта и границы первой версии

### 2.1. Основные пользовательские сценарии

- Создать деталь из понятного шаблона, задать размеры и сохранить её.
- Собрать деталь из объёмных фигур, объединить их или вычесть одну из другой.
- Нарисовать простой профиль и получить объём выдавливанием.
- Сделать отверстия, пазы, скругления, фаски и повторяющиеся элементы.
- Изменить исходный размер, сохранив заданные зависимости.
- Подготовить корпус и крышку с явным зазором.
- Импортировать чужую модель, понять ограничения её редактирования и выполнить доступные операции.
- Проверить модель перед экспортом и открыть результат в установленном слайсере.
- Найти объяснение любой доступной команды и пройти учебный пример.
- Позже — описать деталь обычным языком, проверить предложение AI и применить его.

### 2.2. Приоритеты

P0 — обязательные возможности первой законченной версии v0.1: ручное моделирование, работа с документами, помощь, проверка геометрии, основные форматы и настольная сборка. Этапы M0–M2 последовательно приводят к v0.1.

P1 — AI-помощник, этап M3, версия v0.2. Качество локальной модели проверяется отдельно от качества CAD.

P2 — расширенное моделирование и дополнительные инструменты, этап M4, целевая версия v1.0. Широкая функциональность остаётся целью проекта; её реализация не должна блокировать проверку уже работающих сценариев.

### 2.3. За пределами v0.1

- Собственный слайсер, генерация G-code, управление принтером и облачная очередь печати.
- Анимация, рендеринг сцен, материалы для кино, UV-развёртки.
- Расчёт прочности, сертификация деталей и обещания несущей способности.
- Полноценная замена всех модулей КОМПАС, Blender или промышленной CAD.
- Автоматическое восстановление параметрической истории из STL.
- Генерация точной инженерной детали по одной фотографии.
- Совместное редактирование, маркетплейс, платежи и сервер пользователей.
- Собственные геометрическое ядро, универсальный решатель эскизов или обученная с нуля языковая модель.

## 3. Основа приложения

### 3.1. Рекомендуемая архитектура

По умолчанию выбрать:

- Desktop-оболочка: Tauri 2.
- Интерфейс: TypeScript, React и Vite.
- 3D-вид: Three.js; дополнительные обёртки допускаются, только если упрощают реализацию.
- Геометрический процесс: Python с build123d и совместимой версией OCP/Open CASCADE.
- Контракты данных: версионированный JSON Schema и проверка данных на обеих сторонах.
- Тесты геометрии: pytest; тесты интерфейса и команд — подходящие средства выбранного frontend-стека.
- Формат проекта: собственный документ с графом построения и вложенными ресурсами.

build123d предоставляет параметрическое BRep-моделирование на Open CASCADE. Это основание использовать готовую геометрию для точных деталей, а не разрабатывать её самостоятельно. Документация Tauri предусматривает встраиваемые внешние программы, в том числе упакованный Python. При этом сборка всей связки на Apple Silicon должна быть доказана в M0. [S1, S2, S3]

Kimi должен проверить подход коротким техническим прототипом и зафиксировать решение в ADR. Если обнаружена конкретная проблема упаковки или viewport, допустим один обоснованный переход на Python + PySide6 либо замена build123d на CadQuery. Не разрабатывать два интерфейса и два CAD-backend одновременно.

Закрепить реально совместимые версии зависимостей в lockfiles. Документацию веток latest/dev использовать только после сверки с API выбранного релиза.

### 3.2. Роль альтернатив

- Tinkercad — ориентир простоты взаимодействия: фигуры, отверстия, выравнивание и понятные размеры. Не предполагать наличие доступного встраиваемого движка.
- Blender — возможный будущий инструмент для полигональных и декоративных моделей. Не делать установленный Blender обязательным условием запуска.
- FreeCAD — возможная альтернатива, если приоритетом станет использование готовой инфраструктуры документов и эскизов. Workbench внутри FreeCAD и самостоятельное приложение — разные варианты продукта; не подменять один другим без описания последствий.
- КОМПАС/C3D — не включать в поставку без подтверждённых прав и условий интеграции. Наличие SDK не равно праву распространять ядро в своём приложении.
- OpenCascade.js — резервный вариант для будущего браузерного продукта. Его выбор требует отдельной проверки bindings, памяти и упаковки.

Это архитектурные решения для данного проекта, а не рейтинг CAD-продуктов.

### 3.3. Три представления модели

Разделить:

1. Документ: параметры, операции, UUID, зависимости, единицы, история и ссылки на ресурсы.
2. Точная геометрия: BRep-тела, рассчитанные CAD-ядром.
3. Сетка: производные треугольники для экрана и экспорта на печать.

Источником параметрической модели является документ; вычисленным точным результатом — BRep. Сетка viewport не должна подменять ни то, ни другое.

Изменение поля «Диаметр отверстия» перестраивает отверстие в геометрическом ядре. Изменение надписи, трансформация картинки или растягивание треугольников не выполняют это требование.

## 4. Встроенный гайд и справочник — обязательный P0

### HELP-001. Постоянная доступность

В основном окне всегда доступны кнопка «?» и меню «Помощь → Справочник». Открытие справки также доступно из поиска команд и с клавиатуры.

Для macOS выбрать и проверить сочетание, не конфликтующее с системными командами и вводом текста; показать его в меню. Не рассчитывать только на F1.

Справочник открывается без потери выделения, незавершённых полей и состояния документа. Предпочтительно использовать боковую панель с возможностью расширить её.

### HELP-002. Отключаемые подсказки

Предусмотреть три режима:

- «Обучающий»: подробные контекстные подсказки и предложения подходящих уроков.
- «Краткий»: название, назначение и горячая клавиша.
- «Без всплывающих подсказок»: всплывающие объяснения выключены.

Пользователь может изменить режим в любой момент. Выбор сохраняется после перезапуска. Скрытие подсказок никогда не скрывает справочник, поиск помощи, меню «Помощь» или возможность повторно запустить урок.

Доступные имена и описания для средств доступности сохраняются во всех режимах.

### HELP-003. Объяснение каждого элемента управления

У каждой поставляемой пользовательской команды должен быть стабильный help_id. Это относится к кнопкам, пунктам меню, режимам выбора, инструментам сцены и настройкам экспорта.

У полей параметров должны быть описание смысла, единицы, допустимые ограничения и влияние на результат. Типовые элементы могут ссылаться на общую статью, если из неё понятен конкретный контекст.

Подсказка отвечает на вопросы:

- Что делает действие?
- Что нужно выбрать или ввести перед ним?
- Что изменится после применения?
- Как отменить результат?
- Где посмотреть пример?

Для неактивной команды объяснять причину: например, «Выберите одно или несколько рёбер», а не просто делать иконку серой.

### HELP-004. Режим «Что это?»

После включения режима пользователь нажимает на элемент интерфейса и получает объяснение этого элемента. Нажатие в этом режиме не выполняет исходную команду и не изменяет модель.

Escape завершает режим. Управление с клавиатуры тоже позволяет получить описание сфокусированного элемента.

### HELP-005. Структура статьи справочника

Каждая статья об операции содержит:

1. Название простым языком и используемый CAD-термин, если он есть.
2. Назначение и типовые случаи применения.
3. Где находится команда.
4. Что должно быть выбрано и какие данные нужны.
5. Пошаговые действия.
6. Значение параметров и единиц измерения.
7. Минимальный пример с конкретными размерами.
8. Ожидаемый результат.
9. Частые ошибки и способы исправления.
10. Как изменить или отменить операцию.
11. Связанные статьи и уроки.
12. Версию приложения или статус применимости, если поведение различается.

Статья должна описывать реально доступное поведение текущей версии. Формулировки «нажмите соответствующую кнопку» без её названия и расположения не допускаются.

### HELP-006. Поиск и навигация

Справочник включает оглавление, поиск, связанные материалы, историю переходов и возврат к предыдущей статье.

Поиск работает локально по заголовкам, текстам, названиям команд, синонимам и сообщениям об ошибках. На старте поддержать как минимум пары:

- «дырка» → «отверстие»;
- «скос» → «фаска»;
- «сделать полым» → «оболочка»;
- «закруглить угол» → «скругление»;
- «разрезать» → «разделить деталь»;
- «подогнать крышку» → «зазор»;
- «почему кнопка серая» → «условия выбора инструмента»;
- «подготовить к печати» → «проверка и экспорт».

В результатах показывать короткий подходящий фрагмент. Если функция ещё не поставляется, её статус должен быть явным; выдача не должна вести к несуществующей кнопке.

### HELP-007. «Показать в интерфейсе»

Из статьи можно подсветить нужный элемент реального интерфейса и при необходимости открыть его панель.

Подсветка не запускает операцию, не подменяет выделение и не изменяет документ. Она привязана к стабильному идентификатору команды или элемента, а не к экранным координатам.

Если элемент недоступен в текущем контексте, объяснить необходимые условия. Не выполнять их за пользователя без его действия.

### HELP-008. Пошаговые интерактивные уроки

Уроки используют реальные инструменты и учебные модели. Минимальный комплект v0.1:

1. Навигация: поворот, приближение, перемещение камеры, выбор, виды.
2. Первая деталь: пластина с отверстиями, размеры и отмена.
3. Сохранение, повторное открытие, проверка и экспорт.
4. Втулка или шайба: диаметры, высота, сквозное отверстие.
5. Корпус с крышкой: стенка, дно и зазор.
6. Скругление, фаска и исправление неудачной операции.
7. Импорт STEP и STL: доступные изменения и различия форматов.
8. Проверка печати: ориентация, несколько тел, предупреждения.

В M1 достаточно первых трёх уроков; к завершению M2 обязателен весь комплект. В M3 добавить урок AI-помощника. Уроки по возможностям P2 появляются одновременно с соответствующими функциями.

У каждого урока есть цель, перечень навыков, примерная длительность, шаги, проверка результата и возможность вернуться к нужному шагу. Оценку длительности уточнить после реального прохождения.

### HELP-009. Безопасность учебного режима

Урок по умолчанию открывает отдельный учебный документ или копию примера. Текущий рабочий документ, включая несохранённые изменения, остаётся доступен и не перезаписывается.

Разрешены пропуск, пауза, выход, повтор шага и повтор всего урока. Урок можно завершить раньше; не удерживать пользователя блокирующей цепочкой подсказок.

Прогресс хранится отдельно от рабочей модели. Пропущенный шаг отмечается как пропущенный, а не успешно выполненный.

Завершение шага проверяется по состоянию модели и параметрам. Нажатие кнопки само по себе не доказывает, что создано нужное отверстие.

Если нужная кнопка исчезла из контекста или модель отклоняется от примера, предложить понятный способ восстановить учебный шаг. Не применять неизвестные действия автоматически.

### HELP-010. Работа без интернета и AI

Тексты, поиск, изображения и учебные модели поставляются внутри приложения. Для чтения, поиска и выполнения уроков не нужны интернет, API-ключ, локальная LLM или вход в аккаунт.

AI может дополнительно объяснить найденную статью, но детерминированный справочник остаётся основным источником сведений о продукте.

### HELP-011. Содержание справочника

Обязательные разделы:

- Первые шаги.
- Устройство окна и навигация.
- Все инструменты по отдельности.
- Размеры, единицы и параметры.
- Шаблоны и пошаговые рецепты.
- История построения и отмена.
- Импорт, экспорт и формат проекта.
- Подготовка к печати.
- Ошибки и восстановление.
- Горячие клавиши.
- Словарь терминов.
- Настройки, подсказки и доступность.
- AI-помощник, когда этот модуль реализован.

Объяснять различия детали, тела, грани, ребра, эскиза, сетки, толщины стенки, зазора и допуска на простых примерах.

### HELP-012. Единый источник команд и документации

Создать реестр команд со стабильными command_id, названием, help_id, сочетаниями клавиш, условиями доступности и описанием параметров.

Кнопки, палитра команд, контекстная помощь, AI-каталог операций и ссылки уроков используют этот реестр. Не создавать несколько независимо расходящихся списков.

Материалы хранить в репозитории в понятном редактируемом формате, например Markdown и JSON. Индекс поиска собирать локально при сборке приложения. Дополнительный сервер документации и векторная база не требуются.

### HELP-013. Критерии готовности справки

- 100% поставляемых пользовательских команд связаны с существующей содержательной статьёй.
- У всех видимых специфичных полей есть описание назначения и единиц.
- Сборка проверяет отсутствующие help_id, сломанные ссылки и ссылки уроков на неизвестные command_id.
- Для изменённой функции документация и уроки обновляются в той же задаче.
- В справке нет пустых страниц, Lorem ipsum, TODO или обещаний реализованных позже функций без маркировки.
- Проверено открытие помощи после отключения подсказок и перезапуска.
- Пройден хотя бы один полный урок без сети и без AI.
- Проверено, что рабочий документ не изменился после входа и выхода из учебного режима.

## 5. Интерфейс и взаимодействие

### UI-001. Основное окно

Центр — сцена с деталью. Слева — список деталей и при необходимости история операций. Справа — параметры выбранного объекта или текущего инструмента. Сверху — короткая панель основных действий и всегда доступная помощь. Снизу — единицы, размеры выделения и состояние вычисления.

Дополнительные панели раскрываются по запросу и не перекрывают важные поля на небольшом экране.

### UI-002. Простой и расширенный режимы

В простом режиме показывать наиболее частые действия: создать фигуру, изменить размер, отверстие, объединить, вычесть, скруглить, выровнять, проверить, экспортировать.

В расширенном режиме раскрывать дополнительные параметры, историю, рабочие плоскости и технические настройки. Оба режима редактируют один документ и одинаковую геометрию.

Переключение режима не удаляет параметры и не меняет модель. «Простой» не должен означать приблизительные размеры.

### UI-003. Формулировки

Первые названия ориентировать на действие: «Сделать отверстие», «Скруглить», «Сделать полым», «Разделить деталь». Профессиональные термины давать рядом или в справке.

У важных действий использовать текст вместе с иконкой. Статус нельзя передавать только цветом.

### UI-004. Управление сценой

- Полноценная работа мышью и трекпадом.
- Поворот, панорамирование, масштабирование и «Показать всё».
- Виды сверху, спереди, сбоку и изометрия.
- Ортографическая и перспективная проекции.
- Видимые оси и сетка с шагом.
- Отдельные режимы выбора тела, грани и ребра.
- Подсветка наведения отличается от подтверждённого выбора.
- Gizmo перемещения и поворота сопровождается точным числовым вводом.
- Escape отменяет текущий инструмент или предпросмотр.

Выбор треугольника в viewport должен разрешаться в нужный объект/грань текущей ревизии BRep. Для рёбер нужен отдельный проверенный механизм выбора; нельзя считать рёбрами диагонали триангуляции.

### UI-005. Числовой ввод

Поддержать точку и запятую как десятичный разделитель, отображать единицы возле поля и валидировать ввод до применения.

Пользователь может связать размеры простым выражением, например «длина / 2 - отступ». Выражения разбираются ограниченным parser/AST с разрешёнными операциями; eval запрещён.

Внутри документа хранить выражение и ссылки на параметры. Не заменять зависимость однажды вычисленным числом.

### UI-006. Предпросмотр

Изменение параметров сначала даёт черновой результат. Применение создаёт одну транзакцию; отмена возвращает исходное состояние.

Во время перетаскивания можно использовать упрощённую визуализацию. После отпускания выполнить точный расчёт и явно показать завершение. Устаревший результат пересчёта не должен перезаписывать более новый.

### UI-007. Ошибки

Сообщение описывает действие, причину и возможный следующий шаг. Например: «Радиус 12 мм слишком велик для выбранного ребра. Уменьшите радиус или выберите другое ребро».

Технический код и подробности доступны отдельно для диагностики. Предыдущая корректная модель остаётся видимой и помечается, если новый параметр пока не применён.


### UI-008. Обязательные источники дизайна

По прямому требованию владельца использовать оба источника:

- Impeccable: https://github.com/pbakaus/impeccable

Это обязательная часть разработки интерфейса. Общие рекомендации экономить контекст и не подключать лишние навыки не являются основанием пропустить эти два источника.

Проверенные состояния на 21 октября 2026 года:

- Impeccable: commit dad8dbb3aac21ad1fa236c110315ef4abece23e8.
- Taste Skill: commit 6010f91a9935f1c167dfc500fb1a475681892e6b.

Зафиксировать их в DESIGN_SOURCES.md: URL, commit, прочитанные файлы, назначение и применённые адаптации. При обновлении источника явно записать новый commit и причину. Не полагаться на плавающий main как на воспроизводимую версию.

### UI-009. Применимые режимы

Для основного CAD-окна использовать Impeccable в режиме Operate. Для справочника — Read. В Taste Skill использовать ветку app screens / builder.

Обязательные материалы для ознакомления Kimi:

- Impeccable: README.md, skill/SKILL.src.md и skill/reference/operate.md.
- Taste: README.md, skills/taste-skill/SKILL.md и skills/taste-skill/references/app-screens.md.
- Остальные материалы читать по текущей задаче: проектирование, critique, audit, harden, polish и соответствующие рекомендации по компонентам.

В этих источниках предусмотрены разные подходы для маркетинговых страниц и рабочих экранов. Для PrintForge важны выполнение задачи, ясные состояния и согласованность управления. [S11, S12]

SKILL.src.md в Impeccable — исходник устанавливаемого навыка, а не полный готовый пакет. Не копировать один этот файл и не утверждать, что навык установлен со всеми инструментами. В окружении Kimi использовать реально поддерживаемый способ подключения; если прямой поддержки нет, прочитать материалы и применить процесс явно. Не выдумывать slash-команды и результаты их выполнения.

Инструменты дизайна используются при разработке. Их runtime, диагностические скрипты и сетевые зависимости не входят в приложение и не нарушают офлайн-работу справочника.

### UI-010. Собственный визуальный характер

До большой реализации UI создать краткий PRODUCT.md с назначением и контекстом продукта и DESIGN.md с выбранной визуальной системой.

Рассмотреть до трёх направлений для рабочего редактора, выбрать одно и записать обоснование. Не делать выбор дизайна обязательной остановкой для пользователя, если входных данных достаточно.

Рабочая идея для выбора: спокойная цифровая мастерская, в которой реальная деталь и её размеры занимают главное место, а инструменты читаются как аккуратная система.

Зафиксировать:

- Роли поверхностей, текста, акцента и семантических цветов.
- Шрифтовую систему с полноценной кириллицей и читаемыми цифрами.
- Шкалу размеров текста, интервалы, радиусы, толщины линий.
- Размеры и правила сворачивания панелей.
- Состояния выделения тела, грани и ребра.
- Представление параметров, размеров и ошибок.
- Единый набор иконок.
- Внешний вид справки, подсказок, уроков и их подсветки.
- Правила движения и уменьшения анимации.

Собственный характер должен быть виден в рабочем сценарии. Например, сочетание оформления размеров на модели, контура печатного объёма, панели параметров и интегрированной помощи может стать узнаваемой системой.

Не ограничиваться сменой акцентного цвета в готовом dashboard-шаблоне. При этом сохранять привычное расположение команд, нормальные поля ввода и стандартную навигацию.

### UI-011. Ограничения на шаблонный AI-дизайн

Для данного продукта исключить:

- Декоративные градиенты, свечение, стеклянные панели и анимированные фоны.
- Большие приветственные/маркетинговые блоки внутри рабочего окна.
- Ряды ненужных KPI, декоративные графики и показатели без продуктовой задачи.
- Карточку вокруг каждого поля и вложенные карточки для простых групп параметров.
- Разноцветные подложки под каждой иконкой.
- Огромные скругления, нестабильные отступы и несогласованные кнопки.
- Типографику, которая подходит плакату, но затрудняет чтение размеров.
- Модные анимации, задерживающие ввод, выбор или применение операции.
- Фальшивые аватары, отзывы, достижения, выдуманные счётчики и заглушки в рабочем продукте.
- Обязательные декоративные фотографии и генерацию иллюстраций для заполнения пустоты.

Плоские поверхности, разделители и повторяемые строки допустимы, если помогают работе. Сетка, оси, размерные линии и границы поля ввода — функциональные элементы CAD, их не нужно удалять ради запретов, предназначенных для лендингов.

Нумерация реальных шагов урока сохраняется: последовательность действий важнее декоративных правил страницы.

### UI-012. Плотность, числа и доступность

Основная сцена получает наибольшую площадь. Главные действия доступны из рабочего окна, расширенные настройки раскрываются по запросу.

Размеры показывать с единицами и согласованным округлением; поля и повторяющиеся числа выравнивать. Округление отображения не меняет значение в документе.

Принять проектные цели: основной текст управления от 14 px, второстепенный от 12 px, текст справочника от 16 px с масштабированием. Если плотный режим использует меньшие значения, обосновать его и проверить на целевом экране.

Контраст обычного текста — не ниже 4,5:1; видимые элементы управления и индикатор фокуса должны различаться на фоне. Это критерии проекта, а не заявление о пройденной сертификации доступности.

Цвет не является единственным обозначением ошибки, выбора и состояния проверки. Клавиатурный фокус всегда видим, порядок обхода логичен.

Важные для операции параметры, единицы и кнопки не должны обрезаться на минимальном поддерживаемом окне. При уменьшении окна панели сворачиваются осмысленно.

### UI-013. Реальные состояния вместо одной красивой сцены

Дизайн должен покрывать:

- Пустой проект и понятное начало работы.
- Загруженную деталь и выбор тела/грани/ребра.
- Ввод корректного и некорректного размера.
- Предпросмотр операции.
- Долгий расчёт с отменой.
- Ошибку скругления/вычитания и последнюю корректную модель.
- Потерянную ссылку после перестроения.
- Импорт с выбором единиц.
- Предупреждение печати и ошибку экспорта.
- Несохранённые изменения и восстановление.
- Открытый справочник, поиск, «Что это?» и учебный шаг.
- В M3 — AI-preview, применённый план, Undo и недоступный AI.

У интерактивного компонента реализованы обычное состояние, hover, focus, выбранное/нажатое состояние, disabled, busy и ошибка там, где они имеют смысл.

Во время пересчёта сохранять последнюю корректную модель с обозначением занятости. Не заменять рабочую 3D-сцену скелетоном только потому, что такой приём подходит загрузке карточек.

### UI-014. Визуальная проверка

После первого работающего сценария и перед завершением пользовательского этапа:

1. Запустить настоящий интерфейс с реальной моделью из приёмочных сценариев.
2. Проверить основные экраны при 1280 × 800, 1440 × 900 и 1920 × 1080 логических пикселях.
3. Проверить масштаб интерфейса 125% и 150%, сворачивание панелей и доступность справки.
4. Для сложных состояний выбрать наиболее тесное поддерживаемое окно.
5. Выполнить применимые автоматические проверки источников и собственные проверки доступности/переполнений.
6. Открыть полученные скриншоты и оценить понятность, визуальную иерархию и согласованность.
7. Исправить три наиболее значимые проблемы и повторить предметную проверку.

Использовать предусмотренный выбранной версией Taste app-режим инспектора и соответствующие playbook Impeccable. Если инструмент не запускается в окружении, отметить ограничение и проверить результат доступным способом; не выдавать ручной осмотр за пройденный автоматический аудит.

Проверка web-frontend в браузере не заменяет smoke-test итоговой Tauri .app. При альтернативном native-стеке HTML-инспектор не проверяет native-виджеты.

В каждой итерации — один общий просмотр и исправления; не делать скриншот после каждого изменения пикселя. До трёх раундов художественной доработки достаточно для этапа. Оставшиеся блокирующие дефекты устранить предметно; не снижать критерии ради объявления готовности.

Мобильные проверки, которые инструмент выполняет по умолчанию, не превращают desktop-CAD в мобильный продукт. Зафиксировать неприменимые требования без сокрытия результатов. Для первой версии gate определяется поддерживаемыми desktop-окнами.

### UI-015. Согласование источников и критерий готовности

Требования владельца, точность CAD, сохранность документа, встроенное обучение и доступность имеют приоритет при адаптации внешних рекомендаций.

Impeccable использовать для процесса проектирования и качества взаимодействия; Taste — для выбора и проверки согласованного визуального характера рабочего экрана. Существенные разногласия решить один раз в DESIGN.md.

Обязательный результат дизайна: рабочие компоненты, токены, DESIGN.md, ссылки на закреплённые источники и краткий отчёт визуальной проверки. Скриншот красивого макета не заменяет работающий UI.

При включении файлов этих проектов сохранять их лицензии и необходимые уведомления. Не переносить в репозиторий весь каталог примеров и зависимостей без конкретной потребности.

## 6. Моделирование P0

### CAD-001. Фигуры и размещение

Параметрические прямоугольный блок, цилиндр, сфера, конус и трубка. Для каждой фигуры доступны размеры, положение и ориентация.

Поддержать копирование, независимую копию, перемещение, поворот и группировку. Группа для организации не равна геометрическому объединению.

Нежелательную непропорциональную деформацию точного тела не скрывать под обычным изменением размера.

### CAD-002. Булевы операции

Объединение, вычитание и пересечение точных тел. Инструмент показывает основное тело и тела-инструменты. Их удаление или сохранение после операции — явный параметр.

Результат может содержать несколько раздельных тел; интерфейс должен сообщать их количество.

### CAD-003. Простые профили и выдавливание

В v0.1 поддержать прямоугольник, окружность, кольцо и паз на стандартной плоскости или выбранной плоской грани. Размеры и положение задаются численно.

Профиль можно выдавить на заданную глубину, симметрично либо использовать для выреза. Сквозной вырез выражается как сквозной, а не как случайная большая глубина.

Это ограниченный редактор профилей. Не объявлять его универсальным Sketcher с произвольными ограничениями.

### CAD-004. Отверстия

Поддержать круглое сквозное и глухое отверстие, несколько отверстий по параметрам и прямоугольный паз.

Размеры: диаметр либо ширина/длина, глубина, положение и направление. Координаты можно задавать относительно центра или отступов от выбранных опорных плоскостей/краёв.

Параметры отверстия сохраняются редактируемыми.

### CAD-005. Скругления и фаски

Выбор рёбер, числовой радиус или размер фаски, предпросмотр, редактирование и отмена.

При невозможной операции выводить понятную ошибку. Не подбирать и не применять другое значение молча.

### CAD-006. Полость и толщина

Поддержать открытый корпус из шаблона с независимыми стенкой и дном. Универсальную операцию оболочки использовать там, где ядро возвращает корректный результат; неподдерживаемые формы должны давать объяснение.

Изменение стенки пересчитывает внутреннюю геометрию. Проверять, что размеры полости положительные и не уничтожают деталь.

### CAD-007. Повторение, отражение и выравнивание

- Линейный и круговой массив одинаковых элементов.
- Зеркальная копия относительно плоскости.
- Выравнивание по центру, опорной плоскости и границе.
- Привязки с явным предварительным показом результата.

Параметры массива — количество, шаг или радиус/угол. Различать независимые копии и связанные экземпляры.

### CAD-008. Разделение

Разделение тела плоскостью с сохранением одной или обеих частей. Части сохраняются как именованные тела.

Соединительные штифты и автоматические замки между частями относятся к P2.

### CAD-009. Измерения

Габариты, расстояние между доступными геометрическими объектами, диаметр цилиндрической поверхности, объём и число тел.

Показывать происхождение измерения: точная BRep-геометрия или приближение по сетке. Смена единиц не должна менять физический размер объекта.

### CAD-010. Шаблоны

Минимальный набор:

- Шайба/втулка.
- Пластина с отверстиями.
- L-образный кронштейн.
- Корпус с крышкой.

Шаблон создаёт обычные редактируемые параметры и операции документа. Это не жёстко заданная готовая STL.

В шаблоне корпуса зазор вводится явно и имеет смысл «на одну сторону» либо «суммарный» с однозначной подписью. Обе детали связаны параметрами.

## 7. Параметрическая история и целостность

### DOC-001. Сущности

Минимальные сущности: Document, Part, Body, Feature, Parameter, Reference, ImportedAsset, PrintLayout и PrinterProfile.

У объектов и операций постоянные UUID, имена для пользователя и состояние вычисления. Не использовать подпись пользователя как единственный идентификатор.

### DOC-002. Зависимости

Для одной детали допустима линейная история, между параметрами и деталями — ациклические зависимости.

Пересчитывать затронутые узлы. Выявлять циклы и ссылку на удалённый параметр до фиксации изменения.

Подавление операции, её редактирование и удаление должны показывать затронутые зависимости. Не перестраивать модель в произвольном новом порядке.

### DOC-003. Устойчивость ссылок на грани и рёбра

Запрещено сохранять ссылку только как «Face17» или «Edge8».

Использовать источник операции, смысл элемента, геометрические признаки и информацию об изменении топологии, доступную в выбранном API. UUID и номер треугольника тоже не решают проблему сами по себе.

Если после пересчёта ссылка неоднозначна, операция получает состояние «Требуется повторный выбор». Не выбирать похожую грань молча.

В v0.1 допустим ограниченный набор гарантированно поддержанных ссылок. Его границы должны быть описаны и проверены.

### DOC-004. Транзакции

Ручной инструмент и AI используют одинаковую схему prepare → validate → preview → commit.

Одна операция пользователя отменяется одним Undo. Пакет AI применяется и отменяется целиком. Undo/Redo восстанавливают документ, параметры, тела и зависимые операции.

Сохранение истории построения между запусками обязательно. Сохранение всего стека Undo между запусками необязательно.

### DOC-005. Ошибка вычисления

Разделить последнюю подтверждённую ревизию и черновик. Не позволять экспортировать старую геометрию под видом нового размера.

Если изменение невалидно, последняя корректная модель сохраняется. Пользователь может исправить параметры либо отменить изменение. Экспорт корректной предыдущей ревизии допускается только при явном её выборе.

### DOC-006. Формат проекта

Предлагаемый формат — архив с расширением .printforge, содержащий:

- manifest.json: версия схемы и приложения, единицы, версии геометрического стека.
- document.json: параметры, граф, UUID, настройки документа и размещения.
- assets/: исходные импортированные файлы, необходимые для воспроизведения.
- Опциональные BRep- и mesh-кэши.
- Превью и пользовательские заметки, если они реализованы.

Относительные ресурсы входят в документ. Перемещение файла на другой компьютер не ломает ссылки. Запрещены pickle, исполняемые Python-файлы и автоматическое выполнение кода из проекта.

Кэш не заменяет граф построения. При несовместимой версии ядра приложение не должно молча менять сохранённую форму; показать состояние, использовать доступный снимок для просмотра и предложить пересчёт в копии.

### DOC-007. Сохранение и восстановление

Атомарное сохранение через временный файл, затем замена; проверка ошибок диска и прав доступа.

Автосохранение с интервалом не более 30 секунд после изменений либо эквивалентная стратегия с debounce и максимальным ожиданием. Восстановление после аварии предлагает последнюю доступную копию.

Закрытие изменённого документа предлагает сохранение, отказ от изменений или возврат. Повторный запуск не теряет пользовательские настройки помощи.

### DOC-008. Чтение недоверенных файлов

Ограничить размеры входных файлов, число объектов и распакованный размер архива. Запретить выход путей за временную папку, внешние XML-сущности и автоматическую загрузку внешних ресурсов.

Повреждённый файл должен давать управляемую ошибку без изменения уже открытого проекта.

## 8. Импорт, экспорт и слайсеры

### IO-001. STEP

Импортировать точные тела с учётом единиц. Сохранять структуру и имена в пределах возможностей выбранного импортера.

Импортированное тело не получает историю исходной CAD. Доступны новые операции поверх него. Экспорт STEP выполняется из BRep, с сохранением размеров и количества тел.

### IO-002. STL

Импортировать сетку. Явно предложить единицы и показать рассчитанный габарит перед подтверждением. Не угадывать автоматически, что 1 означает миллиметр или дюйм.

В P0 для импортированной сетки гарантировать просмотр, измерение габаритов, перемещение, поворот и масштабирование с понятным коэффициентом. Точные операции BRep не должны выглядеть доступными для произвольного STL без реализованного преобразования.

Экспорт STL: выбранная деталь либо отдельные файлы по деталям. Сообщать, что файл предназначен для миллиметрового workflow. Для нескольких раздельных тел предупреждать о составе результата.

### IO-003. 3MF

Поддержать обмен моделью по базовым возможностям 3MF: единицы, несколько объектов и их трансформации. Для реализации использовать проверенную библиотеку, например lib3mf через доступную обёртку.

3MF для обмена геометрией и полный проект OrcaSlicer/Bambu Studio/PrusaSlicer — разные договорённости. Не обещать перенос приватных настроек, профилей печати и всех расширений сторонних программ.

Геометрия базового 3MF импортируется в режиме сетки; BRep и исходная параметрическая история автоматически не восстанавливаются. Доступные операции соответствуют mesh-режиму IO-002.

Неподдерживаемое обязательное расширение — явная ошибка. Для неподдерживаемых дополнительных данных показать, что именно не будет сохранено. [S2, S4]

### IO-004. Качество сетки

Viewport и финальный экспорт могут использовать разную детализацию.

Предусмотреть понятные пресеты и расширенные настройки линейного/углового отклонения. Повышение качества меняет сетку, но не номинальные размеры BRep.

Не экспортировать незаметно грубую сетку, которая была построена для быстрого предпросмотра.

### IO-005. Размещение для печати

Отделить положение деталей в изделии от их размещения на столе принтера.

Поворот крышки для удобной печати не должен изменять её положение в сборочном представлении и параметры посадки. Сохранять оба набора трансформаций.

### IO-006. Передача в слайсер

В v0.1 сначала сохранять STL/3MF. Дополнительно разрешить «Открыть в слайсере» для явно выбранного установленного приложения.

Если слайсера нет, экспорт всё равно завершается. Не устанавливать его автоматически. Не утверждать, что модель уже нарезана или напечатана.

## 9. Проверка перед печатью

### PRINT-001. Базовая проверка

Для BRep проверять валидность, наличие замкнутых твёрдых тел и положительный объём.

Для экспортируемой сетки в P0 обязательно проверять вырожденные треугольники, граничные/non-manifold-рёбра, согласованность ориентации и число компонент. Для самопересечений в P0 допустим результат реализованного алгоритма либо явный статус «Не проверено»; обязательный универсальный анализ относится к P2.

Показывать отдельный результат каждой проверки. Если проверка не запускалась или алгоритм её не поддерживает, выводить «Не проверено», а не общий зелёный статус.

### PRINT-002. Профиль принтера

Пользователь задаёт размер рабочей области, диаметр сопла, ориентировочную высоту слоя и материал. Можно сохранить несколько профилей.

Габарит проверяется с учётом размещения и поворота модели. Начальные значения — редактируемые примеры; не приписывать пользователю конкретный принтер.

### PRINT-003. Толщина, нависания и посадки

Анализ минимальной стенки и нависаний допускает приближённые методы. Показывать метод, параметры и непроверенные области.

Для известных шаблонов толщина проверяется непосредственно по параметрам. Если универсальный анализ сложной формы ещё не реализован, это явно указывается.

Порог нависания определяется вместе с системой отсчёта угла относительно направления построения; указывать её в UI и справке.

Геометрический допуск ядра, зазор между деталями и компенсация конкретного принтера — разные понятия. Не применять технологическую компенсацию молча.

### PRINT-004. Исправления

Любое исправление с изменением геометрии даёт preview и обычный Undo. Для импортированной сетки сохранять оригинал и предлагать исправленную копию.

В v0.1 допустимы только фактически реализованные детерминированные исправления. Проверка может обнаружить проблему и объяснить её, не обещая автоматическое исправление.

### PRINT-005. Значение результата

Надпись «Проверки пройдены» означает только прохождение перечисленных проверок. Она не гарантирует прочность, идеальную посадку, качество поверхности или успех печати с произвольными настройками.

Оценка времени, массы и расхода пластика не входит в P0, если она не получена от реального слайсера. Нельзя оценивать фактический расход только по объёму сплошного CAD-тела без учёта заполнения.

## 10. AI-помощник P1

### AI-001. Провайдеры

Единый интерфейс: disabled, локальный Ollama и настраиваемый API-адаптер.

Возможности провайдера определять явно: JSON Schema, tools, изображения, лимиты и поддерживаемые параметры. Совместимость с одним endpoint не означает совместимость со всеми.

Для локального испытания использовать, например, Qwen3-4B-Instruct-2507 в подходящем квантованном формате. Официальная карточка подтверждает существование модели и Apache-2.0; это кандидат для испытаний, а не обещание достаточного CAD-качества. [S6]

Для M3/8 ГБ начать с одной генерации и короткого контекста около 4k, затем измерить память и задержку. Размер весов не равен полному потреблению памяти; увеличение контекста требует дополнительной памяти. [S7]

Модель не скачивается автоматически при первом запуске CAD. Если локальное выполнение слишком тяжёлое, пользователь может отключить AI или явно выбрать внешний провайдер.

### AI-002. Помощь по приложению

На вопросы «Как сделать отверстие?» и «За что отвечает эта кнопка?» AI должен находить актуальные материалы встроенного справочника и давать ссылки на статьи.

Не придумывать команды, панели и сочетания клавиш. Если нужная возможность отсутствует, сказать об этом.

На первом этапе достаточно локального полнотекстового поиска по справке. RAG с векторной базой не является обязательным условием.

### AI-003. Моделирование естественным языком

Обязательные сценарии:

- Создать деталь из одного из поддерживаемых шаблонов.
- Изменить названный параметр существующей детали.
- Добавить отверстие или массив отверстий с указанными размерами.
- Предложить скругление выбранных рёбер.
- Объяснить ошибку операции.
- Объяснить результаты проверки печати.

Сложная свободная форма по картинке, генерация текстур и произвольный reverse engineering относятся к экспериментальному будущему развитию.

### AI-004. Декларативный план

AI возвращает данные по JSON Schema, а не исполняемую программу. Для локального Ollama предусмотрены структурированные ответы с передачей схемы; после получения нужна собственная валидация приложения. [S5]

План включает schema_version, document_id, base_revision, единицы, список разрешённых операций, ссылки на объекты, предположения, нерешённые вопросы и описание результата.

Пример структуры, которую нужно адаптировать к окончательной схеме проекта:

    {
      "schema_version": 1,
      "document_id": "example-document",
      "base_revision": 12,
      "units": "mm",
      "assumptions": [],
      "questions": [],
      "operations": [
        {
          "command_id": "parameter.set",
          "target_id": "example-plate",
          "parameters": {
            "length": 100
          }
        }
      ],
      "summary": "Увеличить длину пластины до 100 мм"
    }

Идентификаторы в этом примере иллюстративные. Реальный план обязан ссылаться на существующий документ и валидные идентификаторы.

### AI-005. Цикл выполнения

1. Получить запрос и компактное описание текущего документа.
2. При необходимости уточнить недостающие размеры или предложить явно обозначенные значения.
3. Получить план по схеме.
4. Проверить структуру, допустимые команды, числовые ограничения, ссылки и ревизию.
5. Рассчитать черновик в геометрическом процессе.
6. Проверить геометрию.
7. Показать результат, список изменений и допущения.
8. Применить только по действию пользователя одной транзакцией.
9. Перед применением повторно проверить актуальность base_revision.

До применения рабочая модель не меняется. Если документ изменился во время генерации, предложение помечается устаревшим и пересчитывается; молчаливое применение запрещено.

### AI-006. Ограничения исполнения

Запрещены eval/exec, shell, загрузка модулей, произвольный Python/JavaScript и файловые операции из ответа модели.

AI и ручной UI вызывают один проверенный CommandService. Допустимые команды и параметры перечислены явно.

Начальные лимиты: до 20 операций на один план, ограничение размера ответа и глубины структур, только конечные числа и проверенные диапазоны. После измерений лимиты можно изменить в ADR.

При ошибке схемы — не более одной автоматической попытки исправления. Повторная ошибка, таймаут или отмена не меняют документ.

### AI-007. Контекст и данные

Передавать только необходимые параметры, выделение, габариты и релевантные операции. Не пересылать все вершины сетки и весь проект при каждом вопросе.

Содержимое имён, заметок и импортированных метаданных — данные, а не инструкции для агента.

Облачный провайдер включается явно; настройки объясняют, какие данные отправляются. API-ключи хранятся в системном хранилище секретов, не в проекте, Git или обычном логе.

### AI-008. Проверка качества

До включения профиля локальной модели как рекомендуемого подготовить фиксированный русскоязычный набор запросов: простые детали, изменения размеров, неоднозначности, невалидные параметры и устаревшие планы.

Зафиксировать модель, digest/версию, runtime, параметры, задержку и пик памяти. Проверять геометрию результата, а не фразу «Готово».

Проектный порог для экспериментального профиля: не менее 80% простых допустимых запросов дают корректный preview после максимум одной попытки исправления. Все запрещённые, отменённые и устаревшие планы не должны изменять документ.

Для подтверждения профиля использовать 20 запросов по три прогона. Это отдельный gate M3, а не обязательный расход токенов при каждой небольшой правке UI.

## 11. Расширенные возможности P2

После прохождения P0 и отдельного AI-этапа последовательно добавить:

- Произвольный 2D-эскиз: линии, дуги, окружности, замкнутые контуры.
- Ограничения: совпадение, горизонтальность, вертикальность, параллельность, перпендикулярность, касание, равенство, размеры и фиксация.
- Индикацию недоопределённости, переопределённости и конфликтов эскиза.
- Вращение профиля, sweep по траектории и loft между сечениями.
- Более сложные оболочки, уклоны и рёбра жёсткости.
- Импорт SVG/DXF для контуров, текст и рельефные надписи.
- Посадочные места под гайки, подшипники и термовставки с явными параметрами.
- Реальную печатную резьбу с профилем, шагом, длиной и технологическим зазором.
- Разделение крупной модели на части, соединительные штифты и замки.
- Калибровочные образцы зазоров и сохранённые пользовательские профили.
- Контролируемые операции с сетками, ремонт и уменьшение числа полигонов.
- Декоративные модели по изображению как отдельный экспериментальный mesh-workflow.

Для универсального Sketcher выбрать существующий совместимый solver после технического и лицензионного исследования. Простая привязка курсора к сетке не заменяет решатель ограничений.

Для резьбы надпись «M5» или декоративная текстура не считаются геометрической резьбой. Физическую совместимость проверять отдельным печатным образцом.

Каждая добавленная функция поставляется со статьёй, контекстной помощью, примером и нужным уроком.

## 12. Процессы и производительность

### TECH-001. Изоляция геометрии

Геометрическое ядро работает в отдельном процессе. Ошибка или зависание native-библиотеки не должны закрывать интерфейс.

Для Tauri предпочтителен versioned IPC через управляемый sidecar. Метаданные передавать сообщениями с request_id, document_id, revision и schema_version. Stdout — протокол, stderr — диагностические логи.

Крупные сетки передавать бинарным ресурсом или ограниченным локальным каналом с handle; не отправлять мегабайты числовых JSON-массивов на каждый кадр.

Не открывать сетевой сервер для CAD без необходимости. Встроенный AI может обращаться к отдельно настроенному локальному Ollama.

### TECH-002. Очередь и отмена

Один геометрический worker на активный документ в первой реализации; число процессов ограничено бюджетом памяти.

Debounce пересчёта при вводе размеров, отбрасывание устаревших результатов, timeout и progress. Если native-операцию невозможно безопасно прервать, завершить worker и восстановить его из последней подтверждённой ревизии.

Применение документа и запись файла защищены от гонок с закрытием, Undo и поздними ответами AI.

### TECH-003. Целевые показатели

Это целевые требования для измерений, а не уже достигнутые результаты:

- Холодный запуск готовой .app без AI — ориентир до 8 секунд на контрольной машине.
- Навигация по обычной сцене — не ниже 30 FPS в контрольном сценарии.
- Поиск по встроенной справке — до 200 мс после загрузки индекса.
- Простая операция над тестовой пластиной — целевой отклик до 1 секунды.
- Длительная операция показывает состояние и допускает отмену; интерфейс не «замирает».
- Рабочий ориентир CAD без AI — до 2 ГБ суммарной памяти процессов приложения на тестовом проекте из 20 простых тел, 100 операций и до 200 тысяч отображаемых треугольников.

Зафиксировать методику, версии ОС, размеры сцены, число прогонов и фактические значения. Не ограничивать функциональность искусственным лимитом в 20 тел; это контрольная нагрузка.

Не заявлять показатели Mac на основании теста только под Linux. Если контрольная машина недоступна, указать непроверенное и подготовить воспроизводимый сценарий.

## 14. Проверяемые сценарии приёмки

Обозначения: координаты в мм; Z — направление высоты. Для аналитических проверок BRep использовать допуск по длине 0,001 мм и по объёму max(0,001 мм³; 10⁻⁶ × ожидаемый объём). Если импорт или ядро требуют другого допуска, обосновать его до проверки и отдельно от печатного зазора.

Для сеточного экспорта использовать параметры дискретизации, например линейное отклонение 0,02 мм, и отдельный критерий: ошибка габаритов до 0,05 мм и относительная ошибка объёма до 0,5% для приведённых простых замкнутых моделей. Цели относятся к тестовым моделям, а не ко всем возможным входным STL.

### AC-01. Пластина и зависимые отверстия — M1

Создать пластину 80 × 40 × 6, центрированную по X/Y, нижняя поверхность Z=0. Четыре сквозных отверстия Ø4 имеют центры (±30; ±10).

Ожидается одно замкнутое тело, габариты 80 × 40 × 6 и объём:

    80 × 40 × 6 − 4 × π × 2² × 6
    = 18 898,407105 мм³

Отступы отверстий от краёв задать параметрами по 10 мм. Изменить длину на 100: центры по X должны стать ±40, диаметр и Y остаются прежними. Новый объём 23 698,407105 мм³.

В текущей сессии Undo возвращает длину 80 вместе с отверстиями, Redo — 100. Затем сохранить, закрыть и открыть проект, проверить размеры и сохранённые зависимости. Наличие прежнего стека Undo после нового запуска не требуется.

### AC-02. Шайба — M2

Наружный диаметр 20, внутренний 6, высота 4. Ожидается одно тело, сквозное отверстие и объём:

    π × (10² − 3²) × 4 = 1 143,539726 мм³

Увеличение внешнего диаметра не меняет внутренний без явно заданной зависимости.

### AC-03. Корпус и крышка — M2

Корпус: наружные размеры 100 × 60 × 30, стенки 2, дно 2, верх открыт. Полость 96 × 56 × 28. Объём корпуса 29 472 мм³.

Крышка: пластина 100 × 60 × 2. Снизу центрированный замкнутый бортик высотой 4, наружные размеры 95,6 × 55,6, внутренние 91,6 × 51,6. Объём крышки 14 355,2 мм³.

В собранном положении крышка занимает Z=30…32, бортик Z=26…30. Между наружной поверхностью бортика и полостью корпуса — 0,2 мм на каждую сторону. Объём пересечения корпуса и крышки равен нулю в установленном численном допуске.

Изменить длину корпуса на 120: полость и крышка перестраиваются; зазор остаётся 0,2 на сторону.

Экспортировать два отдельных объекта в 3MF. Размещение для печати не изменяет положение деталей в изделии.

### AC-04. Кронштейн и ошибочное скругление — M2

Объединить блоки с общим началом координат:

- A: X=0…40, Y=0…30, Z=0…5.
- B: X=0…40, Y=0…5, Z=0…30.

Ожидаемый объём объединения 11 000 мм³; одно связное тело.

Добавить допустимое скругление выбранных внешних рёбер. Затем задать заведомо чрезмерный радиус. Приложение показывает ошибку и сохраняет предыдущую корректную модель.

Изменение исходного размера не должно переназначать скругление на случайное другое ребро.

### AC-05. Форматы — M2

Для пластины AC-01 проверить экспорт/повторный импорт STEP, STL и 3MF.

STEP сохраняет точный размер и отверстия в пределах допуска, но не обещает восстановить авторскую историю. STL открывается как сетка с явным подтверждением единиц. 3MF сохраняет единицы и объекты.

Сравнить результат программно. Дополнительно открыть STL/3MF хотя бы в одном реально установленном слайсере и проверить масштаб и число деталей; если слайсер недоступен, эту часть считать непроверенной.

### AC-06. Сохранение и восстановление — M1/M2

Открыть проект с зависимыми параметрами и импортированным ресурсом. Переместить файл проекта в другую папку и открыть снова.

Проверить отсутствие потерянных ресурсов. Прервать геометрический worker во время операции: UI работает, подтверждённая модель сохранна.

Отдельно прервать приложение после автосохранения: при следующем запуске предложена корректная восстановленная версия.

### AC-07. Скрытые подсказки и постоянная справка — M1/M2

Выключить все всплывающие подсказки, перезапустить приложение и открыть рабочий проект.

Через «?» найти «дырка», перейти в статью «Сделать отверстие», увидеть пошаговый пример и подсветить кнопку. Режим «Что это?» показывает объяснение без выполнения команды.

Проверить, что подсказки остались выключены, а документ и незавершённые параметры не изменились.

### AC-08. Урок без потери работы — M1/M2

Создать несохранённую деталь, запустить учебный урок, пройти несколько шагов, поставить на паузу, закрыть урок и вернуться к детали.

Проверить неизменность рабочей модели и её несохранённых параметров. Повторно открыть урок и продолжить. Проверить настоящий результат шага по модели, а не только факт клика.

Отключить сеть и AI и повторить поиск справки и один полный урок.

### AC-09. Границы печати и проверки — M2

Задать область принтера 220 × 220 × 250 и деталь длиной 230 вдоль X. Получить предупреждение о выходе за стол. Уменьшить длину до 200 и проверить исчезновение именно этого предупреждения.

Импортировать сетку с открытым краем. Получить соответствующую диагностику без утверждения «модель готова».

Нереализованный анализ стенок отображается как непроверенный. Исправление, если доступно, создаёт отменяемое изменение с сохранением исходника.

### AC-10. AI и одинаковая геометрия — M3

Запрос: «Создай шайбу: наружный диаметр 20 мм, внутренний 6 мм, высота 4 мм».

До применения документ не изменён. Preview соответствует AC-02 по размерам, объёму и числу тел. После применения параметры редактируются обычными инструментами; один Undo отменяет всю AI-операцию.

Запрос «сделай отверстие побольше» без однозначного выделения и размера требует уточнения либо явного редактируемого предположения, которое нельзя применить скрыто.

### AC-11. Невалидный и устаревший AI-план — M3

Проверить отрицательный диаметр, неизвестную команду, произвольный код, отсутствующий объект, старую ревизию, таймаут и отмену.

Ни один случай не должен частично изменять документ. Повторная ошибка JSON не запускает бесконечный цикл.

### AC-12. Сборка и полнота обучения — M2

Запустить .app без dev-сервера и проектного Python. Создать и экспортировать реальную деталь.

Проверить реестр поставляемых команд: у всех есть валидные help_id и содержательные статьи. Ссылки и уроки не ведут к отсутствующим элементам.

Проверить мышь, трекпад, клавиатуру, открытие справки и читаемость интерфейса на контрольном экране.

### AC-13. Дизайн рабочих состояний — M1/M2

Проверить реализацию UI-008–UI-015 на реальной пластине, а затем на корпусе с крышкой. В DESIGN_SOURCES.md закреплены оба обязательных источника; DESIGN.md содержит выбранную систему и объяснение её связи с задачами CAD.

На поддерживаемых размерах окна видны нужные поля и единицы; выбор детали/грани/ребра различим; ошибки понятны; подсказки и справочник оформлены последовательно. Нет декоративных блоков, вытесняющих сцену, и элементов, которые только имитируют функцию.

Есть подтверждение просмотра скриншотов и реального взаимодействия. Все блокирующие замечания по читаемости, доступности команд и потере данных закрыты. Если автоматический инспектор не запускался, это прямо указано.

### 14.1. Пользовательская проверка простоты

Цель: человек без опыта CAD по встроенному уроку создаёт пластину с отверстиями и экспортирует её без внешней инструкции; ориентир — до 10 минут после короткого знакомства с навигацией.

Это проверяется реальным прохождением владельца или другого новичка. Автоматический тест не доказывает удобство интерфейса. Если такое прохождение ещё не выполнено, отметить его как ожидающее, а не успешно завершённое.

### 16.1. Начало работы

Прочитать существующий AGENTS.md, данный документ и текущий код проекта. Сохранять уже установленные пользовательские правила и настройки модели.

### 16.2. Проверяемый прогресс

- Работать последовательными вертикальными сценариями.
- Не заменять CAD-геометрию mock-данными в рабочем режиме.
- Не создавать интерфейс с недействующими «готовыми» инструментами.
- Не писать «проверено», если проверка не запускалась.
- Фиксировать фактические ошибки и устранять причину повторяющихся сбоев.
- Для изменений геометрии проверять размеры, объёмы, число тел и повторное открытие.
- Для каждой функции обновлять подсказки, статью и связанные уроки.
- Сохранять полезные промежуточные результаты, если сессия заканчивается.

### 16.3. Экономная работа

Использовать поиск по файлам и целевые чтения, не выводить большие логи и lockfiles целиком. Повторно не читать неизменившееся без необходимости.

Проверки запускать по затронутым компонентам; расширять их для конкретного риска или обязательного gate этапа.

Не подключать несколько агентных фреймворков, Graphify, MCP, векторную базу и дополнительные LLM без выявленной задачи. Навигационные инструменты добавлять, когда размер и связи проекта оправдают это.

Impeccable и Taste Skill прямо требуются владельцем и обязательны для UI по разделу 5. Для них предусмотрены предметное чтение релевантных материалов и ограниченный review.

Не менять выбранную модель и reasoning-настройки без указания пользователя. Наличие большого контекстного окна не является причиной заполнять его ненужными файлами.

Актуальная официальная документация указывает модель kimi-k3 и её API-особенности. Для данного проекта не требуется переустановка рабочего агента. Если создаётся отдельный API-адаптер Kimi, следовать документации, а не общим предположениям о sampling и structured output. [S10]

### 16.4. Минимальные документы в репозитории

- README.md: назначение, запуск, сборка, поддержанные платформы.
- REQUIREMENTS.md: согласованные требования.
- PRODUCT.md: аудитория, назначение и рабочий контекст приложения.
- DESIGN.md: принятая визуальная система и существенные адаптации.
- DESIGN_SOURCES.md: закреплённые версии Impeccable и Taste, пути и роль источников.
- STATUS.md: завершено, текущий этап, подтверждённые проверки, блокеры.
- DECISIONS.md либо короткие ADR: только существенные решения.
- BACKLOG.md: оставшиеся задачи с приоритетами.
- docs/help/: исходники встроенной справки.
- examples/: небольшие воспроизводимые проекты.
- THIRD_PARTY_NOTICES: фактически поставляемые компоненты.

Один актуальный источник статуса; не плодить одинаковые длинные отчёты.

## 17. Определение готовности

Версия v0.1 готова, когда выполнены все P0 и M0–M2:

- Приложение устанавливается/запускается в заявленной конфигурации.
- Ручные сценарии дают настоящую редактируемую геометрию.
- Размеры и зависимости сохраняются после повторного открытия.
- Ошибки операций не повреждают документ.
- STEP/STL/3MF работают в заявленных пределах.
- Экспорт можно передать в проверенный слайсер без изменения масштаба.
- У каждой доступной команды есть объяснение и рабочая ссылка.
- Подсказки можно скрыть, справочник остаётся доступен всегда.
- Учебные уроки работают офлайн и не затрагивают рабочий проект.
- Дизайн использует оба заданных источника и прошёл AC-13 на реальном интерфейсе.
- Выполнены соответствующие критерии приёмки.
- Известные ограничения и непроверенные платформы перечислены честно.

Версия v0.2 дополнительно требует работоспособного AI-модуля с проверенными ограничениями. Версия v1.0 требует согласованного набора P2; наличие roadmap не считается реализацией.

## 18. Основные риски и способы их закрыть

- Упаковка native-библиотек: закрыть пробной сборкой в M0.
- Расхождение картинки и модели: один документ, authoritative BRep и привязка mesh к ревизии.
- Потеря ссылок на грани: ограниченные устойчивые ссылки и явный повторный выбор.
- Слишком широкий первый этап: M1 содержит один полный проверяемый сценарий.
- Сложность интерфейса: постепенное раскрытие функций, понятные названия и встроенные уроки.
- Устаревшая справка: реестр команд, проверка ссылок и обязательное обновление вместе с функцией.
- Нехватка памяти для локальной LLM: необязательный AI, короткий контекст и измерения на целевом Mac.
- Ошибочные действия AI: валидируемый план, preview, явное применение и атомарный Undo.
- Ложная уверенность в печати: отдельные результаты проверок и маркировка непроверенного.
