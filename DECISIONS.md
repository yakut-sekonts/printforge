# DECISIONS.md — существенные решения

## ADR-001. Стек: Tauri 2 + Python/build123d sidecar (принято, M0)

Дата: 2026-10-21. Статус: принято по результатам spike.

**Контекст.** Требования рекомендуют Tauri 2 + TS/React/Three.js + отдельный Python-процесс с build123d/OCP, и требуют доказать связку прототипом и упаковкой до широкого UI (риск: упаковка native-библиотек OCCT в .app).

**Проверено в M0 (macOS 27 arm64, MacBook Pro M3 8 ГБ):**
- build123d 0.13.0 + cadquery-ocp-novtk 8.0.1.1.0: построение тела, вычитание отверстий, скругление выбранного BRep-ребра, пересчёт параметров — объёмы совпадают с аналитикой AC-01 точно (18898.407105 / 23698.407105 мм³).
- Tessellation по граням даёт мэппинг треугольник → грань; мягкая геометрическая ссылка (тип, длина, положение) переносит выбор ребра между пересчётами.
- Документ `.printforge` (zip+JSON) сохраняется и перестраивает модель.
- Экспорт STEP/STL/3MF и чтение результата (STEP — точный; STL/3MF — сетка, ошибка объёма 0.0007% при допуске 0.5%).
- Worker как отдельный процесс с JSON Lines-протоколом; kill -9 worker не трогает родителя, восстановление из последней ревизии работает (pytest, 5/5).
- PyInstaller onefile (115 МБ) с `--collect-all build123d OCP OCP_modules lib3mf` запускается из чистого каталога без venv и даёт точные объёмы.

**Решение.** Основной стек подтверждён; альтернативы (PySide6, CadQuery, OpenCascade.js) не нужны. Замечание: первый запуск PyInstaller-сборки потребовал добавить lib3mf в collect — зафиксировано в команде сборки (README).

**Последствия.** Один геометрический worker на документ; сетки передаются бинарным ресурсом (файл-handle), не JSON-массивами. Версии зафиксированы в backend/requirements.txt и lockfiles.

## ADR-002. Применение Impeccable и Taste Skill в окружении Kimi (принято, M0)

**Контекст.** UI-008 требует оба источника; навыки написаны под другие harness, в Kimi Code прямой установки нет. Выдумывать slash-команды запрещено.

**Решение.** (1) Процесс и правила применяем явно из прочитанных закреплённых файлов (см. DESIGN_SOURCES.md). (2) Автоматические проверки: `npx impeccable detect` и Taste `lint.mjs`/`inspect.mjs --app` как dev-инструменты на собранном frontend. (3) Эти инструменты не входят в поставку приложения.

## ADR-003. FreeLLMAPI как локальный OpenAI-совместимый провайдер для M3 (принято, 2026-10-23)

**Контекст.** Владелец попросил установить github.com/tashfeenahmed/freellmapi и использовать для разработки; затем решено оставить как fallback.

**Состояние.** FreeLLMAPI (MIT) установлен из исходников в `~/freellmapi`, запущен через `npm run dev` (Node 22, отдельный от проекта): API `http://localhost:3001/v1`, дашборд `http://localhost:5174`. Это dev-инструмент, не runtime-зависимость PrintForge. Upstream-ключи провайдеров пока не добавлены — реальные вызовы требуют ключей владельца.

**Решение.** В M3 PrintForge подключает AI через единый интерфейс провайдеров (disabled / Ollama / настраиваемый OpenAI-совместимый endpoint); FreeLLMAPI — один из вариантов такого endpoint'а, включается явно, с объяснением в настройках, какие данные уходят наружу. Переключение самого агента разработки (Kimi) на FreeLLMAPI — действие пользователя через конфиг, не автоматическое.
